架构方案对比

Nuxt 3 前端 + Python 后端的 3 种集成方式

A

Nuxt 3 + FastAPI（推荐）

架构：Nuxt 3 前端 ↔ FastAPI 后端（REST + WebSocket）

Nuxt 3
Vue + SSR
↔
FastAPI
Python
→
Engine
PersonaX

优势

  • 前后端完全解耦，可独立开发/部署
  • FastAPI 自动生成 API 文档（Swagger）
  • WebSocket 原生支持，适合 LLM 流式输出
  • Python 后端可直接调用 OrchestrationEngine

劣势

  • 需要维护两个服务（Nuxt + FastAPI）
  • 跨域配置、进程管理稍复杂
B

Nuxt 3 + Python 子进程

架构：Nuxt API Routes 通过 child_process 调用 Python CLI

Nuxt 3
前端 + API
→
subprocess
调用 Python
→
Engine
PersonaX

优势

  • 单服务部署，最简单
  • 可复用现有 bridge 脚本

劣势

  • 每次请求启动 Python 进程，冷启动慢
  • 无法做流式输出（LLM streaming）
  • 进程间通信复杂，错误处理困难
  • 不适合生产环境
C

Nuxt 3 + Python WebSocket 服务

架构：Nuxt 前端 ↔ Python WebSocket 服务（实时双向通信）

Nuxt 3
Vue + SSR
⇄
WebSocket
Python
→
Engine
PersonaX

优势

  • 实时双向通信，适合诊断工作流
  • 天然支持 LLM 流式输出
  • 可推送实时信号更新

劣势

  • WebSocket 状态管理复杂
  • 不如 REST 直观，调试困难
  • 需要额外的重连/心跳机制
